# albion-companion

Loot logger + DPS meter for **Albion Online**, cross-platform (macOS first-class,
plus Windows and Linux). Port of Windows-only tools: StatisticsAnalysis (Triky313),
ao-loot-logger, albiononlinebot.com.br/loot-logger (visual reference).

Go engine + Wails v2 + React/TS + shadcn/ui. License: **GPL-3.0** (see NOTICE).

## Hard rules

1. **Passive only.** Read network packets. Never send packets, inject, read
   game memory or automate input. This is what keeps the tool ToS-tolerated.
2. **No hardcoded event/operation codes.** Codes move every patch. Use names
   (`events.EvOtherGrabbedLoot`) resolved via `internal/protocol/codes.json`
   (generated by `make codes`, overridable by a user file at runtime).
3. **Never guess packet fields.** Before decoding a new event, grep
   `refs/StatisticsAnalysis` (run `make refs` first) for its `*Event.cs` /
   `*Response.cs` and cite the source file in a comment.
4. **Every decoder gets a table test** with params using the varied int widths
   the Protocol18 deserializer produces (byte/int16/int32/int64). Read params only
   via `protocol.Params` helpers, never type-assert.
5. **Cross-platform from day one.** No macOS-only shortcuts; platform code lives in
   `_darwin.go` / `_linux.go` / `_windows.go` files.
6. **Engine is UI-agnostic.** UI talks only to `internal/app.Service`. No Wails
   imports outside `main.go`/`app.go` at the repo root.

## Commands

| | |
|---|---|
| `make check` | quality gate (gofmt, build, vet, `test -race`, lint, frontend, wails build) |
| `make run-replay` | replay `testdata/synthetic.aorec` through the engine (no game needed) |
| `make run-live` | live capture with the CLI (needs capture permission, see backlog doc) |
| `go run ./cmd/companion-cli -replay X.aorec -dump -only HealthUpdate` | inspect raw params |
| `sudo go run ./cmd/companion-cli -record session.aorec` | record a real session for fixtures |
| `make codes` | regenerate codes.json after a game patch |
| `make refs` | clone StatisticsAnalysis + ao-loot-logger into `refs/` (gitignored) |
| `make dev` / `make build` | Wails app (once scaffolded) |

## Architecture (one line per package)

```
capture  → live pcap / .pcap file / .aorec replay  → Packet{At, SrcIP, Payload}
photon   → Protocol18 Photon parser (copied from albiondata-client fork, MIT)
protocol → Decoder: Photon → Message{Kind, Code, Name, Params}; codes.json
events   → pure decoders Params → typed structs (GrabbedLoot, HealthUpdate, Party*…)
game     → world state: local player, entities (per zone), party, location
loot     → loot session, by-player / by-item, party filter, CSV (ao-loot-logger format)
combat   → damage meter (damage/heal/taken, DPS/HPS, party/PvP filters)
itemdb   → item index → unique name/display name (ao-bin-dumps items.txt, cached)
engine   → wires everything; single decode goroutine; Stats; OnChange topics
app      → UI service (Wails-bound methods + throttled "*:changed" events)
cmd/companion-cli → headless dev tool; tools/gencodes, tools/mkfixture
```

Full design: `backlog doc list` → "Architecture". Packet field spec: "Protocol spec".

## Gotchas

- Event code is in param **252**, operation code in **253** (not the Photon code byte).
- Object ids are per-zone: `game.State` resets entities on every Join response.
- The Protocol18 array-of-arrays decoder was buggy in the fork (returned a string);
  fixed here — keep it matching SA's `DeserializeArrayInArray`.
- macOS capture needs read access to `/dev/bpf*` (sudo or ChmodBPF-style helper).
- ExitLag/VPN tunnels hide traffic from pcap (same limitation as upstream tools).
